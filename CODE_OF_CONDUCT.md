# Codigo de Conducta

## 1. Propagacion de un Entorno Profesional
El objetivo de este codigo de conducta es asegurar un espacio de trabajo respetuoso, eficiente y colaborativo durante todo el desarrollo del proyecto, abarcando la creacion de ramas, revisiones de codigo, discusion de pull requests y mantenimiento de la documentacion.

## 2. Alcance
Estas normas aplican a toda interaccion asociada al repositorio del proyecto, incluyendo:
* Comentarios en commits, ramas e Issues.
* Modificaciones y revisiones en Pull Requests.
* Documentacion tecnica y comunicaciones del equipo.

## 3. Pautas de Comportamiento

### Practicas Aceptadas
* Mantener una comunicacion objetiva, clara y respetuosa durante las revisiones de codigo.
* Aceptar sugerencias tecnicas orientadas a mejorar la calidad del software.
* Respetar las convenciones de trabajo, la arquitectura aprobada y los flujos de integracion.
* Garantizar la seguridad del repositorio omitiendo credenciales o llaves de acceso en el codigo.

### Practicas No Aceptadas
* Uso de lenguaje inapropiado, despectivo o confrontacional en cualquier plataforma asociada.
* Realizar cambios no autorizados o sobreescribir trabajo sin previa discusion tecnica.
* Ignorar intencionalmente las pautas de versionamiento y realizar commits directos sobre la rama `main`.

## 4. Gestion de Desacuerdos
Cuando surjan divergencias tecnicas sobre la implementacion de una mejora o correccion:
1. Se debe priorizar la evaluacion tecnica con base en la estabilidad del servidor y la claridad del codigo.
2. Se debe revisar el historial de control de versiones para comprender el contexto de la implementacion previa.
3. Las decisiones finales deben quedar registradas en la documentacion del proyecto o en el Pull Request correspondiente.
